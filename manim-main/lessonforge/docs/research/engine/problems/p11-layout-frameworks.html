The scene has no structure to lay out

Frames come out sparse, arbitrary and overlapping, and the instinct is to blame Manim. The evidence says otherwise: the IR hands the renderer a flat bag of positioned elements, so no renderer — and no layout framework — can compose what was never expressed.

🎯 Fix strategies — concrete, ordered by payoff (2026-08-03)

Below is the actual path out of the current composition mess, ordered by what measurably improves frames today. Each step is small, deterministic, and independently shippable.

  1. Revive the composition descriptor. It is populated on every scene at billed LLM tokens but consumed only as a log line (transpiler.py:1238). Parse it for a closed vocabulary of layout keywords ("left column", "grid centre", "stacked right", "banner top", "split") and map hits onto the existing layout_template and zone-assignment paths — the consumption machinery already exists at _apply_template_zones (transpiler.py:502). Cost: $0, test_axes_zones.py-style no-manim harness. The split-screen trigger (_maybe_minimize_diagram, transpiler.py:1096) that had to be widened from math-only after a live job split on zero scenes is the class of bug this kills: heuristic triggers chase what the descriptor already said.
  2. Wire shape_overlaps into the repair loop. The probe has measured shape×shape collisions since 2026-08-01 and reports them into the sidecar as shape_overlaps. They are deliberately not counted for repair yet — so two diagrams sitting on each other ship with violations_remaining: 0. The metric has been running passively for days; the data exists to set a threshold. Add the class to _overlap_violations with its own weight, then let the existing accept-if-better repair loop treat it as one more violation class. Cost: ~30 lines, test_overlap_probe.py extension.
  3. Sample mid-transition, not just at beat boundaries. The probe patches Scene.play and runs after it completes — a collision during ReplacementTransform or a slide is invisible. The fix: add an anim_count incrementing per play(), sample a subset (every N frames or every M seconds), and register mid-animation collisions under a distinct mid-transition class. Low-computation overhead given the TTS-stubbed dry-run context. Cost: ~80 lines in _OVERLAP_PROBE_SNIPPET, plus a planted-clip harness.
  4. Add a whole-frame mass/balance solver. Today the transpiler prevents bad outcomes (overlap, clipping) but does not compose — nothing balances visual weight across the frame or aligns unrelated groups to a shared baseline. The simplest form: after all zone claims and graph layout, run a deterministic pass that (a) centres the combined bounding-box of elements, (b) equalises gaps between groups, (c) sizes elements to fill available space. Each is a separate lever behind a flag; start with centre-of-mass. Cost: ~150 lines in transpiler.py, verification by measuring vision-dead-frame count before/after.
  5. Add row and column IR relation primitives. The IR now has connects (edges) and inside (containment). It still lacks the ordinary vocabulary of visual composition: "these three are in a row", "this label sits left of that shape", "equal gaps between peers". Two new RelativePosition relations — "row" and "column" — with gap and alignment parameters, emitted by the transpiler as a VGroup(...).arrange(RIGHT/DOWN, buff=…) that replaces individual zone claims for grouped elements. Pinned in harness, schema re-exported with --regen. Cost: ~200 lines + schema change.
  6. General constraint solver (Cassowary). After rows, columns, insides and edges are declarable, the zone-claiming + fallback-chain system can be replaced with a constraint solver that resolves all six relations simultaneously. This is the clean-sheet solution the table below calls "replaces zone-claiming with a solver" — do it only when the declarable vocabulary covers enough real boards to make the switch worth measuring. Cost: ~500 lines, changes the repair loop's character.
Items 1–4 are each independently shippable. Do NOT bundle them — a single-lever experiment is measurable; a batch change is a guess. Item 1 is the cheapest, highest-ROI move and closes the crack between P05 (intent) and P11 (structure) simultaneously.
🚀 Update 2026-08-01 — step 1 shipped, and it moved the grade

The IR now carries structure. connects: [id_a, id_b] makes an element an edge whose endpoints are computed from the two shapes it joins; relative_positioning.relation: "inside" makes an element a container's content, distributed across the container and shrunk to fit. All geometry stays code-owned (viz_helpers.connector() / place_inside()); the model only names the relationship. Render-verified: the factor tree that drew as one circle and three floating stubs now draws five labelled nodes joined by four real edges, and the tray that drew empty now holds six distributed sweets. Pinned by test_ir_structure.py (36 checks).

Two findings from doing it, both bigger than the feature:

  • The Layout QA Critic was silently deleting elements. Its rewrite was accepted if it merely parsed and kept the class name — nothing checked it preserved the objects. Asked to tidy a tray of six sweets it collapsed all six into ONE mobject and replaced place_inside() with its own arrange_in_grid. This is the real answer to “codegen has too little control”: an LLM pass was rewriting structure the deterministic layer had correct. It is now rejected when it drops an element variable or dissolves a structural helper — the QC pass improves or stands aside, it can no longer destroy.
  • Shape×shape overlap is measured (finding 3 below), under its own shape-overlap class and reported into the sidecar as shape_overlaps — deliberately not counted for repair yet, so a new metric proves itself on real runs first.

Step 3 followed the same day: graph auto-layout. Node positions are now computed from the graph — layered BFS-from-root, distributed per row, scaled into the band between title and caption — overriding whatever coordinates the model guessed. Six nodes piled within 0.1u of a single point rendered as a correct, balanced factor tree. That closes “no layout solver” for the node-and-edge case; rows/stacks are partly covered by place_inside(), and radial/force-directed/flow layouts remain open (this is precisely where Graphviz or ELK become drop-in).

Doing it surfaced a third instance of the critic disease: it rewrote a BOTTOM_CENTER caption's .to_edge(DOWN) into .move_to([0, BODY_Y, 0]) — and BODY_Y is the frame's middle — dropping the caption through the tree. Nothing was deleted, so both earlier guards passed it; a third invariant now protects zone anchors. The lesson generalises: prefer a new invariant over tightening the critic prompt — the prompt is advice, the invariant is a contract. Each guard was found by looking at a rendered frame, never by a test.

Still open: nothing consumes composition (P05), and there is no whole-frame solver — layout is now correct per structure, but nothing balances mass or aligns unrelated groups against each other. Steps 4–5 below stand.

🎯 The question this page answers

“Composition is bad and frames overlap — should we move to another framework?”

Short answer: the framework is not the bottleneck, and switching renderers would carry the defect across unchanged. Three independent findings below place the failure above the renderer, in what the Storyboard IR can say. There are frameworks worth adopting — but they are layout and constraint frameworks, not rendering ones, and they only pay off after the IR can express structure.

🕳️ Finding 1 — the IR cannot express a relationship

A VisualElement can say what it is (type, content, colour, scale) and where it sits (absolute_position, safe_zone_alignment, relative_positioning). It cannot say what it is part of, what it contains, or what it connects. A scene is a flat list.

So a model asked to draw a factor tree does the only thing available: it writes the structure into prose inside one element’s content. Measured on the 2026-08-01 Prime Factorization board:

  • “Two diagonal chalk branches from 84 to circles containing 12 and 7” — one element that is really 2 edges + 2 labelled nodes. The transpiler correctly emits one primitive; the child nodes never exist.
  • “Large coral chalk frame with a short factor branch ending at circles 2 and 6” — a container plus its contents, in one element. Renders as an empty rectangle.
  • “Rectangular tray containing twelve evenly spaced slots” — twelve objects that are not elements. Renders as an empty box (this is the frame the user reported).

The result is structurally guaranteed, not bad luck: a labelled root, disconnected line stubs, and empty panels. Roadmap gap D8 pipeline-roadmap.md §D5b. This is the same lesson as D1 (data-space coordinates) and D7 (containment) one level up — the model is emitting structure as prose, where code should own it.

📐 Finding 2 — there is no layout solver, only collision avoidance

The layout engine is defensively strong and offensively absent. It claims zones, routes around axes, computes label slots, and splits the screen when text piles onto a diagram. Every one of those is a rule that prevents a bad outcome. None of them composes: nothing balances mass across the frame, aligns siblings to a shared grid, distributes a set of peers evenly, or sizes a container to its contents.

That is why a frame can pass every check and still read as arbitrary — one circle top-left, three line stubs, and 60% empty canvas. And it is why the one field designed to carry intent, composition, is written by the LLM on billed tokens and consumed by a log line (P05).

👁️ Finding 3 — the probe is blind to the overlap being reported (partially fixed)

Videos ship with violations_remaining: 0 while a viewer sees things collide. Three distinct faults, two of them still live:

  • text × text — measured and repaired.
  • text × shape — measured and repaired.
  • shape × shape — measured since 2026-08-01, NOT repaired. _ovl_shape_pair_check reports into the sidecar as shape_overlaps under its own class shape-overlap — deliberately kept OUT of _overlap_violations so the metric could be graded on real runs before it ever triggers a repair round. That grading is overdue: the data exists, set a threshold and wire it in (fix strategy #2 above).

Two further blind spots remain: the probe samples after each play() completes, so mid-transition collisions are invisible; and it ignores intersections under 15% of the smaller bounding box, so partial grazes pass. "Zero violations" means "no text collided at a beat boundary", not "the frame is good."

🧭 Why switching renderer will not fix it

The architecture already anticipated backend swaps: everything above the Layout Engine is renderer-independent, and a new renderer is a backend attached at the IR waist — Manim, SVG/CSS, Three.js, Blender and Unity are each analysed in the Renderer Backend Contract reference-architecture.md §21. That analysis stands, and this page does not repeat it.

But note what the contract requires each backend to implement: transpile() that “owns ALL geometry … implements the zone model, anchoring, data-space placement”. In other words every backend re-implements the same flat-list layout logic against the same relation-free IR. Port this scene to Three.js and you get the identical empty tray in 3D. The defect is upstream of the waist.

Rule of thumb: a renderer swap changes how things are drawn. Our failures are about what and where — chosen before any renderer is called.
🧩 Frameworks that do address the real bottleneck

These are layout/constraint systems, adoptable underneath the existing transpiler without touching the renderer. Each stays inside the determinism boundary: the model may choose a structure, the solver computes every coordinate.

Framework / classWhat it would ownFit & cost
Graph layout
Graphviz/dot, ELK, dagre		 Node-and-edge diagrams: trees, flows, cycles, hierarchies. Computes node positions and edge routes from structure alone. Highest immediate payoff. Factor trees, derivation chains, food webs, circuit topologies and org-style diagrams are a large share of STEM boards. Pure-Python options (pydot/networkx) exist; output is x/y, which the transpiler consumes directly. Needs the connects IR field first.
Constraint solvers
Cassowary/Kiwi (matplotlib, AutoLayout)		 Declarative relations — “these three are equal width”, “this sits inside that with 0.2 margin”, “balance mass about the centre” — solved simultaneously instead of by ordered fallback chains. Replaces zone-claiming + fallback chains with a solver. Strong fit for the container/containment gap (D7) and for alignment. Real cost: constraints can be infeasible, so it needs a relaxation policy and would change the repair loop’s character.
Penrose
diagram synthesis from notation		 The closest research match: you declare substance (what exists and how it relates) and style (how that class of thing is drawn); an optimiser produces the diagram. Architecturally the same thesis as this repo, one level higher. Interesting as a design source for the IR even if never adopted as a dependency — its substance/style split is exactly the missing structure/appearance separation. Adoption cost is high (new language, JS runtime).
Box/flow layout
Flexbox/Yoga, CSS Grid semantics		 Rows, columns, stacks, gaps, alignment, and sizing a parent to its children — the ordinary composition vocabulary the engine currently lacks. Cheapest to adopt: a few hundred lines of deterministic Python reproduces the useful subset. Would directly fix “empty tray”, “tiles in a row”, and right-column derivation stacks.
Diagram DSLs
D2, Mermaid, TikZ		 A declarative textual layer for structured diagrams, with layout engines behind them. Tempting for static figures, poor fit here: this pipeline needs per-beat animation control and bbox introspection for the probe. Best treated as a vocabulary reference, not a runtime.
Renderer swaps
SVG/CSS, Three.js, Blender, Unity		 How pixels are produced; probe strategy; camera and 3D staging. Already specified in §21 and orthogonal to this problem. SVG is the cheapest backend experiment and would make the probe cheaper (DOM getBBox), but it composes no better. Defer until the IR carries structure.
🪜 The order that makes any of them pay off — status as of 2026-08-03
  1. Give the IR structure. DONE. connects + relative_positioning.relation: "inside" shipped 2026-08-01. Schema re-exported, contract gate green, render-verified (factor tree: 5 nodes + 4 edges; tray: 6 sweets inside a box).
  2. Teach the storyboard prompt one element per drawable object. Prompt done, gate open. Prompt rule 4c shipped 2026-08-01. The gate is still open: an element whose content names objects it doesn't declare should be a shape-gate rejection — needs measurement first (count "containing", "with", "to" clauses and cross-check against element count).
  3. Graph layout. DONE. BFS-from-root layering shipped 2026-08-01 for node-and-edge scenes (≥3 nodes). Box/flow: place_inside() covers containment-but-not-rows; a general row/column/gap vocabulary is open (fix strategy #5 above). Radial, force-directed, left-to-right flow: open — Graphviz/ELK become drop-in once a second layout kind is wanted.
  4. Extend the probe to shape × shape. Measured, not repaired. The probe has reported shape_overlaps into the sidecar since 2026-08-01, but the class is NOT counted by _overlap_violations — two diagrams colliding still ship with violations_remaining: 0. Next move: set a threshold from sidecar data, then wire into repair (fix strategy #2 above). Mid-transition sampling is still open — the probe measures at beat boundaries only; fix strategy #3 above.
  5. Composition descriptor consumed → layout. Every scene carries a composition field; the transpiler logs it and does nothing else. Fix strategy #1 above closes this, and it is the cheapest single move available ($0, keyword map, no schema change, no metered edge).
  6. Whole-frame mass/balance solver. Fix strategy #4 above. No code exists today for this.
  7. Only then reconsider the renderer, using §21's falsifiable SVG test.
The reason this problem persisted through a fully green build is that the instrument reported success on frames a human calls broken. Shape overlap is now measured — use that data to set the repair threshold, and add mid-transition sampling before claiming any composition improvement is real.
