Narration–animation sync by construction

The voice and the picture share a scene but not a timeline. Entrances fire against whole-cue audio; once they finish, the rest of the beat is dead air. There is no IR where words and animations meet.
problems / 06
S · code owns structure — but structure isn’t meaning T2 applied research Maturity: L1 — approximate by construction
⚙️ Mechanics today
  • Each narration cue is synthesized as one audio block (UniversalTTSService in viz_helpers.py, riding manim-voiceover); the transpiler plays that cue’s animation events against it.
  • Timing on the animation side is content-aware but audio-blind: the _TIMING map (transpiler.py:122-141) assigns durations by element type — it never sees where words fall.
  • The roadmap’s own diagnosis: “Sync is approximate: entrances play against whole-cue audio … the rest of each beat is still dead air until per-element beats land” pipeline-roadmap.md:172-174. Per-element narration beats are open roadmap priority #11 pipeline-roadmap.md:658.
  • A residual language-contract cousin lives here too: a model writing romanized Hinglish directly bypasses the transliteration pass — “no deterministic backstop” for spoken double-speak pipeline-roadmap.md:149-152.
🕳️ The gap — why this is research-grade

“When the narrator says point B, point B should appear” is the entire visual grammar of the 3Blue1Brown genre — and it is currently unexpressible in the Storyboard IR. Cues bind narration to a scene; nothing binds a word to an event. Building that binding deterministically is genuinely hard here for three reasons: word-level timestamps must come from the TTS or an aligner (and this pipeline speaks code-switched Hinglish, where alignment tooling is weakest); re-synthesis to fix timing is expensive (TTS is ~85% of metered cost pipeline-roadmap.md:168, so timing must adapt animation to audio, not the reverse); and pacing itself is pedagogy — the 90-wpm substring bug ("grade 1" in "grade 11", ce/planner_agent.py:42-53) shipped crawling narration to teenagers and nothing measured it.

📎 Evidence
  • Sidecars record animation_beats from 1 to 35 per video (measured) — the beat structure exists; its alignment to speech is unmeasured anywhere.
  • The shared TTS cache (test_tts_shared_cache.py, 10/10) makes repair re-renders bill zero TTS — proof the repo already engineers around audio cost; sync experiments need the same discipline.
  • Dead air is visible to Vision QA as “dead frames” (P03) — two problems, one symptom, neither owning it.
📚 Prior art citation-check before external use

Forced alignment is mature for monolingual speech (aeneas, WhisperX-style timestamping); manim-voiceover itself ships a bookmark API — SSML-like markers in narration that trigger animations mid-cue — which is the genre-standard solution and already in this dependency tree. Code-switched (Hinglish) alignment is the weak edge: ASR-based aligners degrade on romanized mixed-script text, and that degradation is exactly where this system lives. Pacing-for-comprehension has learning-science grounding (segmenting/modality principles) but no computable target.

🪜 Solution sketch — cheap → deep
  1. $0 Bookmarks on the existing tier: let the storyboard mark <bookmark> points in narration (schema field + --regen), transpiler waits on them — manim-voiceover already supports this; the work is IR plumbing and gates.
  2. $0 Measure dead air deterministically: audio-activity envelope vs. event timeline from the script — a per-video dead_air_seconds sidecar field (new health counter ⇒ verify it reads ~0 on a known-good run first, per the voice_degraded lesson).
  3. metered Word-timestamp alignment pass on synthesized audio; compile an Animation-IR schedule that distributes events across the cue instead of front-loading them.
  4. research Code-switched alignment quality, and a pacing model per grade band — what should the words-per-minute and event density be, validated against comprehension, not vibes.
📏 How we’d measure it

dead_air_seconds trend across the video corpus; bookmark-hit accuracy (did the event fire within ±300ms of its word) once alignment exists; and a human A/B — synced vs. front-loaded versions of the same board — to confirm the effort buys perceived quality (feeds P01’s rubric).
