Composition intent never reaches the solver

The layout engine can guarantee nothing collides. It cannot yet realize what the scene is for — and the field designed to carry that intent, the composition descriptor, is currently consumed by a log line.

🔧 Concrete fix strategy (2026-08-03)

The cheapest, highest-ROI move closes this problem AND P11’s structural gap simultaneously: parse the composition descriptor for a closed vocabulary of layout keywords and map them onto the existing zone/template machinery. This is not the research-grade constraint compiler — it is a deterministic, few-line keyword map that the transpiler reads before zone assignment.

Vocabulary to parse (7 keywords covering ~80% of real storyboard compositions):

Composition keywordMaps toEffect
"title banner top" / "banner"layout_template = "TitleStageCaption"first element → TOP_CENTER, last → BOTTOM_CENTER
"split screen" / "left" + "right" / "…stacked right column"layout_template = "SplitScreen"alternates LEFT_CENTER / RIGHT_CENTER
"centre" / "middle" / "grid centre"zone pre-claim CENTER for the named elementthe main visual gets the centre zone
"full canvas" / "fill frame"layout_template = "FullCanvas"no zone constraints — element uses its own positioning
"…stacked" / "…column"arrange DOWN with buff on the named elementsforces vertical stacking, no zone claims needed
"…grid" / "…row"arrange RIGHT with buff on the named elementsforces horizontal row
"left half" / "right half" / "top" / "bottom"zone pre-claim LEFT_CENTER / RIGHT_CENTER / TOP_CENTER / BOTTOM_CENTERsimple spatial override

Implementation: a _apply_composition_hints(composition, elements, used_zones) function (transpiler.py, ~60 lines) called AFTER _seed_axes_zones but BEFORE individual element zone assignment. It never overrides model-authored safe_zone_alignment or an already-templated zone — the descriptor is a hint, not a command, following the "improves or stands aside" pattern. Cost: $0, no schema change, no metered edge. Harness test_axes_zones.py style: a composition string → expected zone pattern, without manim.

This is fix strategy #1 from P11 — the bridge between the two composition problems, and the single cheapest move available. Once landed, the split-screen trigger (_maybe_minimize_diagram) can be retired: the descriptor says "split", so split.
⚙️ Mechanics today
  • Layout is deterministic and defensively strong: zone claiming with axes-aware routing, data-space c2p coordinates, code-computed label slots, and screen management that splits the screen when text piles onto a diagram (_maybe_minimize_diagram, transpiler.py).
  • Every StoryboardScene carries a composition field — a 1–2 sentence layout gestalt the LLM must write (“Every scene MUST include a composition string”, app/storyboard.py:420; schema at app/schemas.py:95).
  • Measured: the transpiler’s only reads of it are logger.info("[COMPOSITION] …") at transpiler.py:822-823 and :1152-1153. Contrast the sibling field layout_template, which IS consumed via _apply_template_zones (transpiler.py:337).
  • Two neighboring symptoms of the same blindness: unknown shape keywords fall back to Circle() (transpiler.py:425, roadmap gap D5 — fixed 2026-08-01), and containment is not a placement primitive — “gas particles” render on or outside their container box (roadmap gap D7 pipeline-roadmap.md:784-791).
  • Update 2026-08-01 — the deeper half is now isolated. With shape types and contained values fixed, what remains wrong is that the IR cannot express structure at all: an element cannot say what it contains or connects to, so models write sub-diagrams into prose and the child objects never exist. That is P11, this page’s structural twin — there is nothing for composition intent to be applied to.
🕳️ The gap — why this is research-grade

The house rule is “models own content, code owns structure” — but composition is content about structure, and it currently falls into the crack between them. The LLM knows the scene’s gestalt (it wrote one, on billed tokens); the solver that places every element never hears it. Result: scenes that are collision-free yet visually arbitrary — the Director’s density measurements (avg 6.0 elements/scene on the optical-fibre board pipeline-roadmap.md:354) patch symptoms (sparseness) without ever seeing intent.

What makes it hard: translating free-text layout intent into solver constraints is a natural-language-to-program problem where the output must stay inside the determinism boundary — the model may choose among layouts but must never emit a coordinate. Get the interface wrong and you reopen the exact door (LLM-owned geometry) the architecture closed. CLAUDE.md already treats the descriptor as the designated channel: “when adding a new layout rule or zone heuristic, check whether the composition descriptor already conveys that intent before coding a new prompt instruction” CLAUDE.md:66-72.

📎 Evidence
  • Populated-but-unconsumed, measured by grep: no layout code reads composition; docs claim otherwise (app/schemas.py:102 says the transpiler “uses it to guide zone assignment” — a doc/code disagreement this audit reports rather than resolves).
  • The split-screen trigger had to be widened after live job bpipueek6 split on ZERO of its scenes — real storyboards write derivation steps as text, not math CLAUDE.md:118-124: heuristics keep chasing what the descriptor already said. The keyword map above replaces this heuristic entirely — if the descriptor says "derivation stacked right column", the transpiler can pre-claim zones before any trigger fires.
  • Particles-outside-their-box — partially fixed 2026-08-01 via relative_positioning.relation: "inside" + place_inside(). Items inside a container are now distributed across its bbox; absolute-positioned children (the old bug) are still possible but the fix-by-construction path exists. CLAUDE.md D5b-iv.
  • The keyword map above (see the green panel) is the cheapest concrete move — parse composition, set layout_template and pre-claim central zones, retire the trigger. P11 fix strategy #1.
📚 Prior art citation-check before external use

Constraint-based layout is mature (Cassowary-family solvers power real UI toolkits); layout synthesis from examples or specs is an active HCI/graphics research line; NL-conditioned layout generation (documents, posters, UIs) works in research settings but without correctness guarantees. The constrained version here — NL intent compiled to constraints, solved deterministically, verified by a probe — is a genuinely nice formulation the field hasn’t packaged.

🪜 Solution sketch — cheap → deep
  1. Close the loop crudely: parse composition for a closed keyword vocabulary and map hits onto the existing layout_template zones. SPECIFIED 2026-08-03 in the green panel above; not yet built. The keyword table, implementation sketch, and harness pattern are all designed. This is the single cheapest move available — ~60 lines of deterministic code, no schema change, no metered edge.
  2. Make containment a placement primitive. SHIPPED 2026-08-01 as relative_positioning.relation: "inside" + viz_helpers.place_inside(). Render-verified; pinned by test_ir_structure.py.
  3. metered Typed LayoutHints IR: a storyboard-time LLM pass translates the free-text descriptor into a small constraint vocabulary (schema field + --regen + admission gate, per house rules). The transpiler solves; the model never places.
  4. research The general compiler: arbitrary composition prose → constraint set with a solvability check and a principled fallback when intent is unsatisfiable (report, don’t silently ignore — the same contract the storyboard gates follow).
📏 How we’d measure it

Harness in the house style (test_axes_zones.py pattern — no manim, no keys): descriptor says “derivation right column” ⇒ elements land in the right column. Downstream: violations at first render (before repair) should fall — the metric P04 already tracks; and intent-match can become a scored dimension in P01’s rubric.
