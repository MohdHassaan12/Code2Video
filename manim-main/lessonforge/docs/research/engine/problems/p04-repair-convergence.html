Repair-loop convergence

The repair loop is the pipeline’s crown jewel — accept-if-better, never lose the original, losers deleted. It is also, measurably, a loop that often stops before reaching zero. Nobody knows when it converges, or why it stalls.

⚙️ Mechanics today
  • The probe prints parseable LAYOUT_VIOLATION: lines; _overlap_error_report compiles them into a brief; an LLM repair agent rewrites the scene; the candidate is accepted only if it renders AND reduces the violation count. Two implementations, same contract: _repair_scenes_parallel (app/render.py:886, per-scene) and _repair_overlaps (app/render.py:647, whole-video).
  • Rounds are capped (OVERLAP_REPAIR_ROUNDS=2 default); every loser is deleted via _discard_video; the sidecar records repair_rounds and violations_remaining.
  • 33 harness checks pin the state machine (test_overlap_probe.py Parts B/C, real renders, LLM stubbed) — including the zero-leaked-artifacts contract.
🕳️ The gap — why this is research-grade

Measured on disk (2026-07-27): 7 of 17 sidecars ship with violations_remaining > 0 — values up to 14; one video still has 6 violations after 3 rounds, another 3 after 4 rounds. Accept-if-better is greedy hill descent where the move generator is an LLM sampling patches: no theory says when it reaches zero, each round costs a metered call plus a re-render, and the round cap is a guess.

The sharper observation: the repair agent is the one place in the whole pipeline where an LLM edits geometry — the exact thing the house thesis forbids (“the LLM never emits geometry” chapter-4-architecture.md:113-116). Layout was computed by a deterministic solver; when it fails, the system asks a language model to nudge coordinates in Python. Meanwhile the solver-side fix for the same defect class measured 4 → 0 violations in one A/B pipeline-roadmap.md:240-241. The research question: should violations be compiled back into constraints and re-solved at the Layout IR level, with the LLM confined to choices code can’t make (what to shrink, what to drop)?

📚 Prior art citation-check before external use

Generate-and-validate automated program repair (GenProg lineage) documents exactly this plateau behavior: patches that pass the checker while the defect class persists. Constraint-based layout (Cassowary-family solvers) shows the alternative: encode the violation as a constraint and re-solve — deterministic, terminating, explainable. Greedy local search vs. restart strategies (when to stop patching and re-plan the scene) is classic optimization; the novelty here is the hybrid: a solver that owns geometry, an LLM that owns semantic concessions, and a probe as the objective function.

🪜 Solution sketch — cheap → deep
  1. $0 Taxonomy first: parse the residual violations out of the 17 sidecars’ job logs and classify by type (text-on-text / clipped / text-over-shape) and by scene shape — attribute upstream-first, the roadmap’s own discipline.
  2. $0 Deterministic pre-repair: before any LLM round, retry the transpiler with escalating structural moves it already owns — _maybe_minimize_diagram, zone reassignment, font-size step-down. Only what survives goes to the LLM.
  3. metered Violation→constraint compiler: turn each probe line into a constraint on the Layout IR and re-transpile (re-solve), keeping accept-if-better as the outer guard. Measure rounds-to-zero against the current loop on the same boards.
  4. research A convergence policy: when to stop repairing and re-storyboard — i.e., admit the scene is over-packed (ties to P05) — with the give-up signal learned from the taxonomy, not guessed.
📏 How we’d measure it

The metric already exists and is already durable: violations_remaining in every sidecar. Target: the 7/17 residual rate → 0/N on a bulk suite, at equal or lower repair spend (needs P02’s ledger). Pin new operators in test_overlap_probe.py style — real renders, stubbed LLM.
