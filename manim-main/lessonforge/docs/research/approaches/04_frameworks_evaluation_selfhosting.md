# 04 — Explanation frameworks by level, evaluation at scale, self-hosting

Researched 2026-10-08. Scope: evidence base for the three draft lesson frameworks, cheap/reliable judging of generated lesson videos, and open-weight options per pipeline stage. Claims marked **[uncertain]** could not be verified against a primary source; cost figures marked **[est.]** are back-of-envelope.

### Proposed revisions to the three draft frameworks

Evidence-driven changes: (a) every level starts by activating prior knowledge and pre-training vocabulary (Rosenshine #1, pre-training principle); (b) "explore" in a linear video must be *guided* (prediction prompts), since open exploration without guidance is the weakest case in the guidance literature while *prediction-then-reveal* is what Muller/Kapur actually tested; (c) the pitfall becomes a refutation; (d) worked-example density decreases and problem-first increases with level (expertise reversal); (e) every level ends with retrieval, not a summary.

**Foundation (low prior knowledge, roughly classes 5–8)** — *activate → concrete → guided-explore → name & represent → model → faded practice → recap-retrieve*
1. **Activate** (20–30 s): one question on something they already know that the lesson builds on; names the 2–3 terms that will appear (pre-training).
2. **Concrete**: a single tangible situation (money, cricket scores, a tiffin box), shown physically on screen (CRA "C").
3. **Guided-explore**: narrator asks for a prediction, pauses ~3 s, then shows what happens; at most two such cycles. Not open-ended.
4. **Name & represent**: move C→R→A explicitly; the pictorial representation and the symbol appear side by side and the mapping is stated.
5. **Model**: one fully worked example in small steps, each step narrated while it animates; no on-screen sentence text.
6. **Faded practice**: two completion problems (last step removed, then last two), each with a pause cue and the answer revealed; target ~80% success.
7. **Recap-retrieve**: 2 retrieval questions with pause, then a one-line summary.

**Standard (some prior knowledge, roughly classes 8–10)** — *hook-question → activate → idea → worked example → faded practice → refutation → recap-transfer*
1. **Hook-question**: open with the motivating problem or a plausible wrong intuition the viewer is invited to hold (curiosity + sets up the refutation).
2. **Activate**: 15 s of prior-knowledge review and term pre-training.
3. **Idea**: the concept in ≤ 2 chunks with explicit boundaries ("that was part one"); one representation only.
4. **Worked example**: full solution narrated over animation, key equation on screen.
5. **Faded practice**: completion problem(s) with pauses; one self-explanation prompt ("why does this step work?") at the highest-risk step.
6. **Refutation**: state the misconception as a claim, show where it leads, break it with a counter-case.
7. **Recap-transfer**: one question in a new surface context, then summary.

**Advanced (strong prior knowledge, classes 11–12 / competitive)** — *problem-first → claim → conflict → proof → limits → transfer → recap-metacognition*
1. **Problem-first**: pose a problem the viewer should actually attempt before any instruction (productive failure); invite a specific guess.
2. **Claim**: the precise statement of the result.
3. **Conflict**: why it is not obvious; contrast cases including the likely wrong attempts from step 1.
4. **Proof/derivation**: segmented by logical moves, structure signposted; one or two "why is this step legal?" pauses; fewer worked steps than lower levels.
5. **Limits**: hypotheses, counterexamples, where it fails.
6. **Transfer**: a genuinely different problem (exam-style), attempted by the viewer, then solved briskly.
7. **Recap-metacognition**: restate the shape of the argument and what to be able to reproduce; one retrieval prompt.

### Adopt first
1. Encode each level as a *pedagogical system instruction* (stage list + guidance density + success-rate target + the Mayer narration rules), following LearnLM's framing.
2. Make "pitfall" a refutation and add a prediction-pause to every level (the two largest effects found that are cheap in a video: d ≈ 0.8).
3. Build a 300-item stage-labelled corpus from Khan Academy and MMMC/3b1b transcripts to validate the frameworks and seed Q3 fine-tuning.

### Open questions
- Hinglish narration: no studies found on personalization/modality effects in code-mixed narration; **[uncertain]** whether conversational-style gains transfer.
- Pause cues in a non-interactive video: the segmenting evidence is mostly learner-paced; the right pause length for Indian school viewers is untested.
- Whether modern neural TTS still incurs the "voice principle" penalty vs human narration (the original studies used older synthetic voices) **[uncertain]**.

### Adopt first
1. **Planted-fault calibration set first, judges second.** No judge output enters the pipeline until it clears per-fault recall/FP gates; this is the only cheap way to get a reliability number for our own content.
2. **Split the judge by modality and observability.** Text LLM over script + scene plan with binary, stage-anchored rubric items derived from LearnLM's 25 items and our frameworks; VLM over frames/video for layout, overlap and narration–visual sync (the half where TEB showed ρ ≈ 0.7).
3. **TeachQuiz-style learner-model quiz as the end-to-end metric**, with a fixed quiz bank per lesson and pre/post/delta reported; use the level's human-calibrated delta as the ship threshold.

### Open questions
- TeachQuiz leakage: how much of the "post" score is recoverable without the video at all for well-known topics; needs a no-video control per topic.
- Hindi/Hinglish judging: no published reliability numbers for LLM judges on Hinglish tutoring text; expect lower agreement.
- Agentic video mode on Gemini 3.x Flash: token savings are claimed, but whether it skips the exact frames where a layout fault occurs is untested.

TTS is ~55–60% of the API bill, so it is the stage where self-hosting pays first. A dedicated 4090 is ≈ $250/month; break-even against the API path is roughly 1,500–2,500 lessons/month, and Manim rendering (CPU) dominates wall-clock either way. Below that volume the API path is cheaper once idle time and ops are counted.

### Adopt first
1. **Self-host TTS first**: Kokoro for English drafts now; evaluate Veena and Chatterbox-Hindi in a blind Hinglish listening test against Gemini TTS/Bulbul; this is the largest API line item and the one with real open options.
2. **MMS_FA / WhisperX alignment on the same GPU** — near-zero cost, removes the per-minute ASR charge, and alignment-to-known-script is more robust than ASR for Hinglish.
3. **Qwen3-VL-8B-FP8 as the frame-level visual critic**, gated by the Q2 planted-fault set; keep the text model on the API until ≥ 500 graded, stage-labelled scripts exist, then try a Gemma 4 12B / Sarvam-M LoRA against the API model in A/B.

### Open questions
- Hinglish TTS quality is unbenchmarked publicly; prosody on code-switch boundaries and English technical terms inside Hindi sentences is the risk.
- svara-TTS licence and Veena's training-data provenance need checking before commercial use.
- Whether a style/structure LoRA trained on English Khan/3b1b transcripts transfers to Hindi/Hinglish scripts, or whether a separate Hinglish corpus is required.
- Open VLM critics process frames, not audio; narration–visual sync therefore has to be checked via alignment timestamps + script, not by the VLM "listening".
