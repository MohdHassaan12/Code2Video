# How others solve long-form consistency and correctness in generated lesson videos

Research date: 2026-10-08. Scope: agentic Manim/lecture-video generators, long-form story generation with explicit state, program-aided math verification, LLM-as-judge reliability for pedagogy. Every number is from the cited source; where only an abstract was readable, that is stated.

Adoption-cost column assumes lessonforge as it is: Python owns structure (plan once, chapter-by-chapter writing against a ledger of running example / glossary / established facts / last lines), the model writes words, and there is already an arithmetic lint and a reviewer-model rubric pass that emits Python-checkable claims.

---

## PROBLEM A — Long-form consistency

### A.1 Approaches

### A.2 Adopt first

1. **Typed chapter contract with mandatory continuity fields** (CourseBlueprint + EduStory actions). Each chapter is a JSON object the writer must fill: `{chapter_id, action_tags:[INTRODUCE|DERIVE|APPLY|SUMMARIZE…], entities_used, callback_to_prior: "<names a specific thing from the previous chapter>", running_example_step, forward_hook, narration}`. Code validates `entities_used ⊆ ledger ∪ introduced_here`, that `callback_to_prior` contains a ledger term, and that the running example appears in every non-summary chapter; reject-and-regenerate on violation. Why first: cheapest change, and the only approach with a direct measurement that instructions fail where schema succeeds (0/9 vs 9/10).
2. **Ledger update as an explicit, validated writer output** (NstAgent). After the narration the writer emits one `ledger_update` with `upsert_glossary / add_established / add_future_requirement / resolve_future_requirement`; Python applies it, so the next prompt is `frozen plan + ledger JSON + last lines`, never accumulated prose. `future_requirements` fixes "promised earlier, never delivered". Measured CED reduction at linear cost with unchanged prose quality.
3. **Chapter-boundary drift metric** (EduStory KDR) **plus terminal-window contradiction check** (NstAgent/ConStory). Per boundary the judge gets `E_t`, `S_t`, chapter t+1 and returns the KDR JSON; `KDR = drifted_boundaries/(T−1)`. Separately run a ConStory-style checker on the last two chapters with earlier chapters as evidence, labelled with the 19 subtypes. These are the only continuity metrics in the sources not built on a holistic "flow" score that TEA showed is uncorrelated with humans.

### A.3 Tried and did not work

- Outline-in-every-prompt plus "connect to the previous scene / don't repeat the intro" (TEA): judged fine by an LLM whose flow agreement with humans is ρ=0.16; no state object.
- Prompt markers as grounding (CourseBlueprint): 0/9; a single global prompt "collapses" per-section signals into one tone.
- Post-hoc local editing for consistency (Re3 Edit): no measurable gain; detection ROC-AUC 0.684; comparing all statement pairs yields "a sea of false positives".
- One long prompt for the whole piece (EduStory B0): KDR 0.41, worst condition; single-call generation tops out near 10K words (NstAgent).
- Rolling summaries as memory (NstAgent RollSum): CED 7.24 vs 4.86 with explicit state at 100K.
- Human spot-checks as gold standard for consistency: experts F1 0.281, recall 0.139 (Lost in Stories).
- Per-section parallel generation with no cross-references (Code2Video, Paper2Video): cannot carry a running example by construction.

### A.4 Open questions

- No source measures narration continuity for Manim lessons of 6–20 minutes; KDR numbers are for 30–90 s pixel video, CED for fiction.
- Does a mandatory structured `ledger_update` cost narration quality here? NstAgent says no for fiction.
- The 12–19% entropy signal on error segments is cheap if logprobs are available; untested as a trigger for targeted re-review.
- Reranking 2–3 candidate chapters (Re3) vs regenerate-on-violation is compared nowhere.

## PROBLEM B — Correctness

### B.1 Approaches

### B.2 Adopt first

1. **Claims → SymPy/`assert` programs, written by a different model family, run sandboxed, accepted only on unanimity** (SymCode + X-SGRV + pessimistic verification). Reviewer schema: `{claim_id, sentence_span, kind: numeric|geometric|identity|quantifier, verify_code: "def verify(facts): …assert…"}`, where `facts` is the code-owned lesson state (numbers, triangle coordinates, which corner is right). Run each `verify`, feed tracebacks ≤2 rounds, fail any claim without an assert. Why first: the only family with measured false-acceptance control (171/171) and it slots into the existing "Python-checkable claims" design.
2. **Scene-graph grounding of geometric and labelled claims** (SGA extraction + Khanmigo "load the solution first"). Build the worked solution and geometry in Python before narration; expose it to the writer as facts and to the verifier as `facts`. Extract the symbolic scene graph from the chapter's Manim code without rendering and check that the corner the narration names is the corner the code marks. "Right angle at the wrong corner" is unverifiable from text, and SGA shows VLM critics miss geometric errors.
3. **Evidence-grounded, locked, calibrated reviewer rubric plus two regex gates** (Rulers + curriculum grounding). Binary checks that must quote a span, grounded in the lesson glossary/plan, calibrated on ~100 seeded-error lessons (wrong sum, swapped corner, answer-before-pause, "always"). Gates needing no model: (a) no answer token between `pause_start`/`pause_end`; (b) `always|never|every|all` must be paired with a ledger-registered theorem id or rewritten. Holistic judges are near-noise for accuracy (ρ=0.14), evidence-cited checks raise QWK by 0.15–0.29, and the two worst failure types are mechanically detectable.

### B.3 Tried and did not work

- Same-model self-verification: 13.8% false acceptance, 30.8% on hard items, from correlated errors (X-SGRV); benefit shrinks as solver and verifier converge (arXiv 2512.02304).
- Joint chain-of-verification (verifier sees the draft): repeats the draft's hallucinations (CoVe).
- Holistic LLM/VLM accuracy scores: ρ=0.14 (TEA), r=−0.17 (ManimAgent), inter-judge consensus without human calibration (arXiv 2606.03043).
- VLM critics for geometric correctness: insensitive to errors humans reject 84.4% of the time (SGA).
- RAG over Manim docs (TEA): snippets "often irrelevant or overly generic", more hallucinated calls and tokens.
- Calculator alone (Khanmigo): errors persisted until the model was also made to enumerate solution paths and load human-authored solutions first; still not error-free.
- Code verification of non-formalizable claims (SymCode): synthetic geometry, induction and combinatorics cannot be asserted; 56% of code-mode failures are misformalization — the verify program can encode the wrong claim.
- Rigid rubric semantics (curriculum marking): fixing the meaning of directive verbs made the judge conservative and wrong.

### B.4 Open questions

- No source verifies *narration against animation* semantically (SGA is layout-only; TEA shows video exposes errors text hides). The scene-graph cross-check in B.2(2) is a proposal, not a result.
- Who checks that `verify()` encodes the claim the sentence makes? X-SGRV's answer is a verifier that never sees the solver's reasoning; transfer to prose claims is untested.
- Rulers needs 100–200 labelled calibration items per domain; nobody reports how many seeded-error lessons suffice for a chapter-level reviewer.
- "Answer before the pause" has no published metric beyond the "Revealing" label (76% agreement); the regex gate assumes the answer is a known token and fails for prose answers.
- Overclaim ("always") detection appears in no source as a metric; the quantifier gate is lessonforge's own design.
