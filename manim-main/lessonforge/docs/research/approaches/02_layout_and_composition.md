# How others solve layout and composition in generated Manim video

Research note, 2026-10-08. Scope: text overlap, off-frame objects, text-over-shape, top-heavy frames, stale objects between beats, collisions during transitions. Our baseline: a dry-run per-`play()` bounding-box probe (`src/lessonforge/layout_probe.py`), fixed two-column chapter layouts, one deterministic "re-lay compact" repair accepted only when findings decrease, and a gemini-2.5-flash frame critique that produced false "dead frame" findings at scene starts.

Frame facts used below: Manim CE and manimgl both use an 8-unit-high frame (14.22 wide at 16:9), `to_edge` buff 0.5, `next_to` buff 0.25, `SMALL/MED_SMALL/MED_LARGE/LARGE_BUFF` = 0.1/0.25/0.5/1.0, default font size 48 ([CE constants](https://github.com/ManimCommunity/manim/blob/main/manim/constants.py), [3b1b default_config.yml](https://github.com/3b1b/manim/blob/master/manimlib/default_config.yml)).

## 2. The three to adopt first

### 2.1 Upgrade the probe into an SGA-style verifier (persistent vs transient, MSVs, exemptions, composition score)

Why first: the only approach with a human-preference result against a VLM critic; deterministic; seconds per pass; a superset of what we run. It closes RQ-17's two known gaps: nothing is measured mid-animation, and "zero violations" says nothing about composition.

Data structures (in `layout_probe.py`):

```python
Item      = {id, cls: "text"|"geom"|"mark"|"deco"|"image", bbox:(x0,y0,x1,y1),
             centroid, w, h, parent_id, src_line, opaque_plate: bool}
Snapshot  = {beat, play_idx, alpha, t, items: list[Item]}
Violation = {kind: overlap|text-over-shape|off-frame|illegible|cramped,
             a, b, frac, msv:(dx,dy), alphas_seen: list[float], persistent: bool,
             src_lines:(la, lb)}
BeatScore = {overlap, in_canvas, legibility, separation, density,
             grid_occupancy_4x3, top_heaviness}
```

Where it runs: the probe now fires after `Scene.play` returns. Add a patch on `Scene.update_to_time` (CE's per-frame hook inside `play_internal`) that snapshots at alphas {0, .25, .5, .75, 1} of each play (SGA uses 11; start at 5 and measure). A pair is `persistent` if it overlaps at alpha 1 or at ≥3 consecutive samples; transient-only overlaps are reported, not counted (SGA's resting rule; also the crossfade class B found by eye). Exemptions by class pair as in SGA: enclosure (`SurroundingRectangle`, `Brace`) over its target, pointer tip touching target, label centred in a container, text over an opaque plate (ours already, fill ≥0.6). MSV = shortest axis-aligned displacement making intersection ≤0, emitted in the finding (`shift label by (0, +0.35)`), so "re-lay compact" becomes a targeted repair, and any model repair gets a ±5-line window plus the vector.

Composition: per beat-end snapshot compute SGA's density band [0.10, 0.35] and 4×3 occupancy, plus top-heaviness (foreground area in the top half) for RQ-08's "upper two-thirds" defect. Acceptance changes from "findings decrease" to "persistent violations decrease and BeatScore does not fall".

### 2.2 A slot registry with measured fit (Code2Video's grid and occupancy, Remotion's measure-then-fit)

Why: Code2Video's largest single gain (+37.6 points) came from making placement discrete, and 8×8 was worse than 6×6, so coarse named regions are the right granularity. Our two-column templates are already regions; missing are the occupancy table and a fit guarantee.

```python
Slot      = {name:"title"|"left.diagram"|"right.1".."right.4"|"caption",
             region:(x0,y0,x1,y1), pad:0.25, max_items, fit:"wrap"|"scale"|"split",
             font_floor: 24}
Occupancy = {beat: {slot: [item_id]}}        # built at codegen, checked at dry run
FitResult = {slot, item, measured:(w,h), action:"ok"|"wrapped"|"scaled:0.8"|"overflow"}
```

Where it runs: at codegen the model names a slot and supplies content (how `GuidedChapter` steps already work). In the dry run, before a beat's first `play`, the compiler instantiates each item, reads its extent (Text via width param, MathTex after LaTeX; cache by content hash since LaTeX dominates dry-run time) and applies the slot policy: wrap at slot width, scale down to the font floor and never below (§3), else emit `overflow` and split the step across two beats. The occupancy table also handles stale objects: at beat end every slot not carried forward is released and the compiler emits the FadeOut; an on-screen mobject no slot owns is a `stale` finding (OmniManim routes these "remnant" issues separately from layout). Where a slot has two legal placements, generate both and rank with the probe (LayoutPrompter's ranker).

### 2.3 Pixel diagnostics instead of the VLM gate; VLM kept narrow, reference-anchored, non-blocking

Why: every source that measured a frame-level VLM layout judge found it weakly or negatively aligned with humans (TEA ρ=0.42; ManimAgent κ=−0.07; SGA ρ=0.24 against geometry plus over-correction of intentional overlaps; canvas study 20% layout-bug recall without a reference). Our false "dead frame" findings have the deterministic cause videomaking #84 hit: a black threshold below the background value, sampled at fixed fractions that land on fade-ins.

Design: `frame_diag.py` over frames sampled at cue ends (from `timeline.json`) plus 2 fps during transitions (OmniManim). Foreground fraction = pixels differing from the theme background on a 160×90 downscale; dead frame only if <0.5% for longer than one cue and not at a cue start. Frozen = changed-pixel fraction between samples; flicker = oscillating foreground count; density on a 6×8 grid with ≥60% cells flagged. These cover what geometry cannot see: post-render only, camera moves, images. The VLM then runs only on frames already flagged, with a known-good reference frame from the same chapter and a zoomed crop, asked a closed question (overflow / blank / fine, Paper2Poster form); advisory only, logged, with precision measured on labelled fixtures before it may block (videomaking #97's order). Longer term, let a model write small verifier programs against the `Snapshot` DSL and keep those that agree with labels (weak-verifier aggregation).

## 3. What did not work, per the sources

- **VLM as the layout gate.** TheoremExplainAgent: metric–human Spearman 0.42, raters' α 0.31. ManimAgent: Pearson −0.17, κ −0.07 on 37 videos, forcing a fallback to human rating. SGA: VLM scores compress into a 10.5-point band where geometry separates 14.4; the VLM critic "misinterprets intentional overlaps as errors", readability 3.64 vs 6.09 for raw on intentional-overlap trials; 30–90 s per iteration. Code2Video's human study: humans notice brief occlusions VideoLLMs miss. Canvas study: layout-bug recall 20%, precision reaching 100% only with a bug-free reference screenshot. videomaking: the VLM said "ok" on glyph-over-glyph frames, and its prompt cited reference frames that did not exist.
- **Prompt rules alone.** TEA's prompts demanded safe margins and spacing and still scored 0.57–0.65 against 0.73 for human videos; Code2Video without anchors 45.2 vs 82.8.
- **Finer grids.** 8×8 anchors scored below 6×6 (77.2 vs 82.8): more freedom, more clutter.
- **Auto-shrink.** Paper2Poster lists "unusably small scales" among its failure modes; TEA reports "inconsistent object sizes"; SGA's legibility term penalises anything below 0.15 units because shrinking is the degenerate fix; Remotion's `fitText` has no maximum and is single-line, so users cap it; community guidance floors fonts at 18 at 1080p. Shrinking must stop at a floor and become a split.
- **Beat-end-only checks.** B's 40 beat-end checks reported 0 violations while a crossfade overlap was found by eye; OmniManim's ablation: interpolation-aware planning 0.763 → 0.734 without it, and the keyframe planner as a whole → 0.491.
- **Pixel checks with untuned thresholds.** videomaking's empty-frame check (threshold 15, background 28) never fired; its frozen check flagged a moving dot; fixed 25/50/75% sampling missed sections.
- **VLM commenter without exemplars.** Paper2Poster: tree alone overflowed everywhere; commenter alone still overflowed; only negative/positive exemplars plus zoom converged, and a 7B VLM still overflowed.
- **RAG of Manim docs for layout.** TEA found retrieved docs "overly generic", raising cost without gain.

## 4. Open questions

1. Precision/recall of our probe on a labelled fixture set with planted faults and valid intersections (RQ-17's criterion). SGA reported no item-level correlation of MVQS with humans; nobody has.
2. How many alphas per play? SGA uses 11 under a <5 s budget; our dry run already pays LaTeX. Measure 5 vs 11 on the crossfade fixture.
3. How long is a "brief occlusion" humans notice (Code2Video reports sensitivity, not duration)? It sets the `persistent` threshold.
4. Do SGA's density band and 4×3 occupancy transfer to a two-column lecture layout, or does each template need its own band?
5. `SVGMobject`/image bounding boxes are reported too small in CE ([manim #3265](https://github.com/ManimCommunity/manim/issues/3265)); images are the class we have never measured.
6. Can a reference-anchored, cropped, closed-question VLM reach usable precision on our frames? No published number; videomaking's label-measure-enable order is the only disciplined path seen.
7. Is generating two placements per slot and ranking by the probe worth the dry-run time?
8. Camera motion or 3D breaks every geometry approach above (SGA states 2D only) — RQ-18.
