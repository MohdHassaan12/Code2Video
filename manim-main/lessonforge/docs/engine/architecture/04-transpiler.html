🖥️

Screen management — _maybe_minimize_diagram

A cue that piles free-standing text onto an on-screen diagram → diagram shrinks to the left half, text stacks in a right column. Trigger: any math or ≥2 text-ish elements; never on cue 0, never for diagram-anchored labels. Widened from math-only 2026-07-20 after live job bpipueek6 split ZERO scenes — real storyboards write derivations as text.

🎭

Built-in animation feel

Elastic ease_out_elastic entrances, staggered reveals, same-zone collision fallback, asset fallback (SVG/molecule → Text) — all deterministic, no LLM decoration

⚠️ Traps this design pins

Cross-scene NameError: per-scene scripts know only their own vars; both emitters fall back to the raw storyboard id on a miss — dropped events, not broken renders (killed 3 of 4 scenes on the 2026-07-20 Dalton run before the fix)

Selective-import guard: from viz_helpers import X silently satisfied the star-import check → NameErrors + skipped font injection. Guards must test the exact form they guarantee

repr() quote styles: the Indic-strip guard matched only Text("…") while the transpiler emits Text({repr(content)}) — single quotes — so the English-on-screen contract was dead on the whole transpiler path

🧭 Design rules

Sole full-scene codegen path — don't add a second one

Don't move structural decisions back into prompts — the LLM writes content (storyboard JSON), the transpiler decides layout, order, animation

Keep both emitter behaviours when editing — master path shares a namespace; per-scene path is isolated
